WURFL Capabilities

Powerful tools for building device-aware web apps 📱💻

WURFL gives developers access to hundreds of device capabilities — queryable properties describing the hardware and software of the requesting device. Here are three a developer can test against any visiting device.

📱

Is Mobile

is_mobile Boolean

Returns true if the requesting device is a smartphone or feature phone, or false for desktops and laptops. This is one of the most commonly used WURFL capabilities — a developer can query it server-side to decide whether to serve a lightweight mobile layout, redirect to a mobile subdomain, or load a different set of CSS and JavaScript assets, all before a single byte of HTML is sent to the browser.

Example: if is_mobile == true → serve a single-column layout with touch-friendly buttons and smaller image assets to save bandwidth.
is_mobile
📐

Screen Width

resolution_width Integer

Returns the physical screen width of the device in pixels — the actual hardware resolution, not the CSS viewport width. An older feature phone might return 240, while a modern flagship smartphone could return 1440. Knowing this lets a developer pick the right image size on the server before sending any content, instead of shipping a 2000px hero image to a screen that only shows 360px.

Example: if resolution_width < 400 → serve product-thumb-small.jpg instead of product-hero-large.jpg, cutting image payload by up to 80%.
resolution_width
👆

Touch Screen

is_touchscreen Boolean

Returns true if the device has a touchscreen, or false if it relies on a keyboard or mouse. Knowing this allows a developer to conditionally load a touch-optimised JavaScript library, enlarge tap targets in CSS (Apple recommends at least 44×44pt), and replace hover-based dropdowns with tap-to-open menus — all decided server-side before the page loads.

Example: if is_touchscreen == true → add a touch-ui class to <body>, increasing button padding and enabling swipe-based product carousels.
is_touchscreen
ℹ️ Developer note: WURFL capabilities are queried server-side through the WURFL API (available for Java, PHP, Python, and other languages). The device's User-Agent string from the HTTP request header is matched against the WURFL database, and the capability values are returned — letting you adapt your response before any content reaches the client.
